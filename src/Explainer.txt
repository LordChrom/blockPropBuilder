
Statements are separated by line or by semicolons
Leading and trailing whitespace are removed, other than that spaces separate values in lists
The first character of each statement determines what operation is performed.
The text after the first character again has leading and trailing whitespace stripped, and what remains is the
    "argument" for the operation

If the first character does not specify an operation or a comment,
    then the most recently specified operation is treated as a list of identifiers, separated by spaces, on which to
    perform the operation.
-------------------------------
+ sets name of current property to the argument
	optionally, '&' may be used as a separator to set multiple properties at once
	each property named will have whitespace removed from the start and end, but not middle
	property value is set to ""
	provided identifiers will have the named property set to the property value

= sets the current property value to the argument, while retaining property name
	provided identifiers will have the named property set to the argument of this statement

- identical to plus, except that the property value is set to null, which makes a property be treated as unset,
	also prevents this property from being inherited from item's ancestors

; anywhere in line, splits line into multiple statements

@ forms groups. The argument is the group name, and the identifiers will become members of this group
    traits applied to the group will be inherited by the group members, except where - is used

# nop. Argument is ignored
------------------------------------------
example:
-----
   + my hat   &   my  cat
+my hat&my  cat
# this is a comment, the previous two lines are functionally identical.
cobblestone
# previous line set "my hat" and "my  cat" to "" for cobblestone, which means those will return true for has()

+color;=3;  red_concrete red_wool;  # you can pack multiple statements in one line separated by semicolons
